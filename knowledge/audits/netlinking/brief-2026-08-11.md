# Audit Brief — Netlinking (marketplaces backlinks)
Date : 2026-08-11 · Auditeur : Lovable · Baseline : première itération

## 1. Objectif métier
Permettre à un utilisateur Crawlers d'acheter des backlinks thématiques depuis les marketplaces intégrées (Accesslink.ai, Rocketlinks, Getfluence) sans quitter l'app, avec commission Crawlers de 10 %, puis de suivre la vie du lien (publié / perdu) dans le temps.

## 2. Cas d'usage principaux
- Premium → recherche d'opportunités par thème/budget/DR → liste d'offres triées prix total croissant
- Premium → commande d'une offre → débit wallet → suivi de statut jusqu'à `live`
- Pro Agency → suivi hebdomadaire du portefeuille de liens, alerte si lien perdu
- Parménion / Stratège Cocoon → axe `offsite_authority` recommandé quand l'autorité off-site est le frein
- Admin → réconciliation des commandes provider ↔ wallet (remboursements)

## 3. Logique métier clé
- Commission 10 % recalculée serveur (`netlinking-order` rejette un pricing client divergent)
- Wallet : `dev_wallet_debit` avant appel provider, `dev_wallet_credit` en refund si le provider échoue
- Cache catalogue 24 h (`netlinking_catalog_cache`, clé = providers+langue+thème+filtres)
- Cycle de vie commande : draft → pending → in_progress → live → (lost | rejected | refunded | cancelled)
- Surveillance hebdo (`cron-netlinking-monitor`) : polling provider + vérification HTML de la présence du lien, alerte `anomaly_alerts` si perdu
- Dépendances : tables `netlinking_providers`, `netlinking_orders`, `netlinking_catalog_cache`, `dev_wallets` ; edge `netlinking-search`, `netlinking-order`, `netlinking-webhook`, `cron-netlinking-monitor` ; APIs externes Accesslink / Rocketlinks / Getfluence
- Contraintes projet : mem://tech/security/multi-tenant-isolation-fr, mem://constraints/session-and-ip-security-fr, mem://features/pro-agency/quota-monitoring-fr, mem://tech/architecture/global-config-fr, mem://ui/navigation/global-header-fr

## 4. Critères de qualité attendus
| Axe | Cible | Mesure |
|---|---|---|
| Fonctionnel | recherche renvoie des offres réelles ; commande débite et crée la ligne ; monitor détecte un lien perdu | test manuel + logs |
| Intégrité financière | zéro écart wallet ↔ commandes ; aucun double débit ; refund systématique sur échec provider | SQL de réconciliation |
| Performance | recherche p95 < 4 s (cache < 300 ms) ; monitor < 150 s pour 500 commandes | logs edge |
| Coût | 0 appel LLM sur ce module (déterministe) ; coût provider tracé par commande | `ai_gateway_usage`, `netlinking_orders` |
| Sécurité | isolation `auth.uid()`, webhook signé, pricing recalculé serveur, secrets provider jamais exposés | `security--run_security_scan` |
| UX | design system Crawlers (violet/or/noir/blanc, pas d'emoji, boutons bordure+texte), états vides et erreurs explicites, top-up wallet accessible | revue visuelle |
| Vérité affichée | aucun provider affiché comme actif s'il n'est pas réellement câblé | revue code + UI |

## 5. Benchmark concurrentiel
- **Rocketlinks / Getfluence (en direct)** : catalogue profond, filtres fins, facturation intégrée. Faiblesse : aucun lien avec l'audit SEO du site, aucune priorisation des pages cibles.
- **Semrush Link Building Tool** : prospection + suivi de liens gagnés/perdus, intégré à l'audit. Faiblesse : pas d'achat intégré, prospection manuelle par email.
- **Babbar.tech** : métriques d'autorité et de sémantique off-site supérieures (BAS, valeur induite). Faiblesse : pas de marketplace, pas d'exécution.
- **Barre à atteindre / dépasser** : Crawlers doit être le seul à relier *diagnostic* (page pilier faible en autorité identifiée par Cocoon/Parménion) → *achat ciblé* → *vérification de survie du lien*, avec ancres suggérées cohérentes avec le maillage interne. À valider / corriger par toi.

- Backend : `supabase/functions/netlinking-search/index.ts`, `netlinking-order/index.ts`, `netlinking-webhook/index.ts`, `cron-netlinking-monitor/index.ts`
- Frontend : `src/pages/Netlinking.tsx`, `src/routes/app/netlinking.tsx`, entrée `ConsoleSidebar.tsx`
- Tables : `netlinking_providers`, `netlinking_orders`, `netlinking_catalog_cache`, `dev_wallets` (lecture)
- Intégration : axe `offsite_authority` dans `cocoon-strategist`, consommation par Parménion / workbench
### Hors scope
- Wallet Paddle et facturation (audité séparément)
- Disavow / désaveu de domaines toxiques
- Bloc Marché & Autorité de l'audit stratégique (déjà audité)

## 7. Signaux à mesurer
- SQL : répartition des `netlinking_orders` par statut ; commandes bloquées en `draft`/`pending` > 7 j ; écart somme débits wallet `source_ref like 'netlinking:%'` ↔ `total_ht_cents`
- Logs edge : `netlinking-search`, `netlinking-order`, `cron-netlinking-monitor` (taux d'erreur, providers réellement joignables)
- Cache : taux de hit `netlinking_catalog_cache`, entrées expirées non purgées
- Front : états vides quand 0 offre, gating plan, accessibilité du top-up wallet
