# Audit Brief — Parménion (Autopilot orchestrator)
Date : 2026-08-11 · Auditeur : Lovable · Baseline : `knowledge/audits/parmenion/brief-2026-07-08.md` + `audit-2026-07-08.md` (findings #169 → #176)

## 1. Objectif métier
Piloter en autonomie les sites sous Autopilot (audit → diagnose → prescribe → execute → validate) pour publier du contenu SEO/GEO original dans le CMS cible sans intervention humaine, en respectant les gardes sémantiques et le budget LLM.

## 2. Cas d'usage principaux
- Cron 6 h → `autopilot-engine` réveille chaque cible active → `parmenion-orchestrator` exécute la phase suivante
- Admin (Fantômas) → force un cycle sur un domaine depuis `ParmenionDashboard`
- Prescribe → plan déterministe 8 tâches via `cocoon-strategist`, écrit dans `parmenion_decision_log`
- Execute → `job_queue` découplée → `iktracker-actions` / `dictadevi-actions` / CMS interne `crawlers.fr`
- Validate → `autopilot-validate-deployed` re-scanne le HTML publié
- Pull externe → `parmenion-api` + `@parmenion/sdk` (worker client)

## 3. Logique métier clé
- 5 phases, sans rollback ; `implementation_mode = 'auto'` publie directement (status `published`)
- Gardes : backlog (>5 planned = pause), cannibalisation, saturation, cluster diversity (cap 2/cluster), persona rotation, dedup Jaccard synonym-aware, anti-hallucination
- Breathing Spiral : `compute-spiral-signals` + binding cluster
- Crawl guard : skip si crawl en cours (`cron-crawl-scheduler`)
- Images : `_shared/parmenion/imageOriginality.ts` (Gemini 3.1 flash image), NO_TEXT_GUARD
- Tables : `parmenion_targets`, `parmenion_decision_log`, `autopilot_configs`, `architect_workbench`, `persona_rotation_log`, `saturation_snapshots`, `job_queue`, `iktracker_slug_memory`
- Mémoires applicables : `mem://tech/autopilot/parmenion-v3-fr`, `backlog-guard-fr`, `auto-config-on-target-fr`, `cluster-diversity-engine-fr`, `persona-decomposition-engine-fr`, `dedup-synonym-layer-fr`, `anti-hallucination-gates-fr`, `breathing-spiral-engine-v5-fr`, `spiral-cluster-binding-fix-fr`, `parmenion-hardening-fixes-fr`, `editorial-governance-fr`, `content-brief-fr`, `image-originality-fr`

## 4. Critères de qualité attendus
| Axe | Cible | Mesure |
|---|---|---|
| Fonctionnel | ≥ 90 % des cycles terminent sans phase en erreur ; aucun des 8 findings de baseline non traité et non justifié | `parmenion_decision_log` + diff findings |
| Fiabilité | Validate découplé (≥ 30 min après Execute), retry_count borné à 3, plan 8 tâches intégralement consommé | decision_log |
| Performance | Cycle < 5 min p95, aucune phase > 300 s | logs edge |
| Coût LLM | < 5 ¢ / cycle prescribe, 100 % des appels loggés | `ai_gateway_usage` |
| Sécurité | isolation `(domain, tracked_site_id, auth.uid())`, route admin-only, RLS + GRANT | `security--run_security_scan` + grep |
| Qualité contenu | Jaccard < 0.5 vs existant, diversité cluster et persona respectées, images sans texte | `saturation_snapshots`, `persona_rotation_log` |
| UX | violet / or / noir / blanc, boutons bordure sans fond, aucun emoji | revue `ParmenionDashboard` |

## 5. Benchmark concurrentiel (à corriger par l'utilisateur)
- **SEO.ai** — génération + publication WordPress, UI simple ; pas de garde saturation, pas de validation post-déploiement
- **Byword.ai** — publication massive automatisée ; single-shot, aucune anti-cannibalisation
- **Frase autopilot** — brief + writer intégrés ; aucune vision multi-site multi-cycle
- **AutoblogAI** — pilote blog complet ; zéro garde sémantique
- Barre à atteindre : rester le seul autopilot avec validation post-déploiement par re-crawl, gardes sémantiques cumulées et mémoire pluri-cycle — et corriger la fiabilité d'exécution (là où les concurrents, plus simples, échouent moins).
