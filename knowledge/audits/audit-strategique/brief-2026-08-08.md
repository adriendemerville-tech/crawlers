# Audit Brief — Audit stratégique IA (bloc Marché & Autorité inclus)
Date : 2026-08-08 · Auditeur : Lovable · Baseline : première itération

## 1. Objectif métier
Donner à un utilisateur Crawlers un diagnostic de position stratégique de son domaine (marché, concurrents, autorité, toxicité des liens, visibilité organique et IA) et en déduire une priorisation d'actions exécutables par Parménion / Stratège Cocoon.

## 2. Cas d'usage principaux
- Free → lance un audit stratégique sur son domaine → obtient un diagnostic lisible avec au moins un axe d'action clair
- Premium → relance l'audit après corrections → constate une évolution mesurable (comparateur T0/T+30)
- Pro Agency → exporte le rapport PDF pour un client → le document est défendable face à un rapport Semrush/Ahrefs
- Admin → vérifie que les constats produits atterrissent dans `architect_workbench` et sont consommés par l'Autopilot

## 3. Logique métier clé
- Chaîne : `strategic-orchestrator` → `strategic-crawl` / `strategic-market` / `strategic-competitors` → `audit-strategique-ia` → `strategic-synthesis`
- `_shared/domainAuthority.ts` : `normalizeDomainRank` (courbe puissance, plafond 92), `computeBacklinkToxicity` (pénalité jusqu'à −45 %)
- Visibilité organique injectée depuis `rankingOverview` (trafic estimé, mots-clés, position moyenne, top 3/10)
- Constats écrits dans `architect_workbench` (dont `backlink_toxicity`) puis lus par `cocoon-strategist` et Parménion
- Dépendances externes : DataForSEO (backlinks, ranked keywords), Lovable AI / OpenRouter (synthèse), PageSpeed
- Gating : audit accessible à tous ; profondeur concurrentielle et export PDF selon plan
- Contraintes projet : mem://tech/audit/domain-authority-block-fr, mem://tech/strategic-audit/engine-v5-fr, mem://tech/architecture/keyword-universe-ssot-fr, mem://tech/security/multi-tenant-isolation-fr

## 4. Critères de qualité attendus
| Axe | Cible | Mesure |
|---|---|---|
| Fonctionnel | un audit complet finit sans timeout et produit ≥ 1 finding workbench | run réel + SQL |
| Fiabilité des scores | aucun score saturé (≥ 90) sans justification ; écart autorité vs Semrush < 15 pts | comparaison Semrush |
| Priorisation | les positions/trafic réels pondèrent les recommandations, pas seulement la technique | lecture prompts |
| Performance | latence p95 < 90 s par phase | logs edge |
| Coût LLM | < 8 ¢ par audit complet | `ai_gateway_usage` |
| Sécurité | RLS + GRANT + isolation `auth.uid()` | `security--run_security_scan` |
| UX | violet/or/noir/blanc, pas d'emoji, pas de bleu IA, boutons bordure + texte | revue visuelle |

## 5. Benchmark concurrentiel (validé : Semrush + Babbar + Haloscan)
- **Semrush** (Domain Overview + Backlink Analytics) — rôle : étalon de calibration des chiffres de marché (autorité, trafic estimé, mots-clés, toxicité). Vérifiable via connecteur, donc benchmark mesurable. Faible sur GEO et sur l'exécution.
- **Babbar.tech** — concurrent frontal du bloc Marché & Autorité : BAS / SVI / Induced Strength mesurent l'autorité par thématique sémantique, soit la promesse même de notre bloc + cocon. Si notre autorité recalibrée ne tient pas face à Babbar sur un domaine FR, le différenciateur sémantique est déclaratif.
- **Haloscan** — étalon de prix et de terrain FR (~50 €/mois, freelances et petites agences). Fixe la barre d'acceptabilité de nos paliers gratuit et Premium.
- Écartés volontairement : **Ahrefs** (pas d'accès API dans le projet → benchmark non vérifiable ; Semrush suffit comme étalon backlinks), **SE Ranking** (aucun angle discriminant vs Semrush/Haloscan), **Screaming Frog** (crawler technique → déplacé dans le périmètre de l'audit n° 2 Crawl).
- Barre à atteindre : chiffres de marché aussi crédibles que Semrush, autorité sémantique défendable face à Babbar, et supériorité nette sur la priorisation actionnable (quoi corriger, dans quel ordre, avec quel gain attendu) — c'est le seul axe où ni Semrush, ni Babbar, ni Haloscan ne produisent d'exécution.
