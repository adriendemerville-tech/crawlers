## 2. Oublis

- O1 — 4 outils tarifés dans `mcp_tool_pricing` (`get_fix`, `list_findings`, `keyword_research`, `backlink_snapshot`) sans implémentation ni feature backend. Ils sont `enabled=false` en base, donc invisibles dans `list_tools_pricing`, mais la grille reste incohérente avec le manifeste (14 outils publiés).
- O2 — `src/lib/mcp/billing.ts:36-90` (`authorize()`) est du code mort : aucun outil ne l'importe, tout passe par `crawlers-api`. Deux « juges uniques » coexistent, dont un inerte.
- O3 — Les tokens ne sont rattachés au `mcp_call_log` que si `metadata.job_id` est fourni ; le chemin `billing.ts` ne le fournit pas.
- O4 — `dismissed` et `failed` ne sont pas exposés dans les statistiques Workbench admin (25 + 10 lignes actuelles invisibles). `src/components/Admin/WorkbenchAdmin.tsx:113-118`
- O5 — Aucune purge définitive des items Workbench terminaux : l'hygiène ne fait que passer en `dismissed`, seule la dédup supprime.
- O6 — Doublon de calcul de récompense : `parmenion-feedback` (snapshots `audit_impact_snapshots`) et `pericles_measure_rewards` (fenêtres `gsc_daily_positions`) écrivent les mêmes colonnes avec des sources différentes.
- O7 — Aucun écran d'exploitation pour les commandes `deploy_partial` : une commande payée avec déploiement échoué est invisible hors `passe_order_events`.
- O8 — `0015` n'ajoute aucune contrainte CHECK sur `site_deploy_status`/`gmb_deploy_status`.
- O9 — Crons non versionnés : `autopilot-engine-cycle`, `parmenion-feedback-daily`, `pericles-measure-rewards-daily`, `workbench-hygiene-cron` existent bien en base (vérifié) mais ne figurent dans aucune migration → perdus en cas de reset.
- O10 — `mcp_daily_usage` a une policy SELECT mais aucune policy d'écriture (fonctionne seulement via `security definer`).
- O11 — Double mécanisme canonical sur les pages piliers : `pageHead({path})` côté route et `useCanonicalHreflang` côté composant.

## 3. Optimisations possibles

- Fusionner les deux chemins de mesure de récompense en un seul juge (garder la RPC SQL, supprimer le calcul dans `parmenion-feedback`) : moins de code, aucun risque d'écrasement.
- Centraliser `ACTIVE_STATUSES` (aujourd'hui dupliqué dans `_shared/periclesPass.ts:24`, `workbench-hygiene/index.ts:13`, et divergent dans `marina/index.ts:4932` qui inclut `deployed`).
- Ajouter un TTL de purge (par exemple 90 jours) sur les items `dismissed`/`failed` du Workbench.
- Contrainte SQL `cost_micro % 10 = 0` ou exposition directe en micro-crédits pour supprimer l'arrondi `cost_micro/10` de l'API.
- Verrou (`FOR UPDATE`) ou contrainte d'unicité sur `mcp_daily_usage` pour rendre le plafond journalier exact.
- Versionner tous les crons dans une migration idempotente.
- Poser un canonical + liens réciproques entre `/audit-geo-seo` et `/audit-seo-geo`, ou fusionner les deux pages.
