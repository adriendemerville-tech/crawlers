# Audit Brief — Agent SEO (crawlers.fr)
Date : 2026-08-16 · Auditeur : Lovable · Baseline : première itération

## 1. Objectif métier
L'Agent SEO doit maintenir et améliorer en continu le référencement du site crawlers.fr lui-même (blog + landings), en produisant des propositions validables par un humain, alignées sur les standards SEO/GEO/AEO que Crawlers vend à ses clients.

## 2. Cas d'usage principaux
- Admin → clique « Lancer » dans l'onglet Agent SEO → une page est scorée et des propositions de code sont créées.
- Admin → dépose une directive (`agent_seo_directives`) → le dispatcher relaie la consigne, l'agent l'exécute sur la cible nommée.
- Agent (autonome) → aucune directive en attente → auto-ciblage de la page la moins récemment optimisée (blog prioritaire).
- Agent → détecte un manque de couverture → crée un brouillon de page (`seo_page_drafts`) à approuver puis publier.

## 3. Logique métier clé
- Scoring 7 axes : contenu 20 %, structure Hn 15 %, mots-clés 15 %, maillage 15 %, métadonnées 15 %, E-E-A-T 10 %, densité 10 %.
- Garde-fous : routes interdites (home, `/audit-expert`, `/app/*`, `/console`, `/profil`) ; landings en mode prudent (≤ 10 % de modification) ; blog en carte blanche ; validation humaine obligatoire.
- Dépendances actuelles : tables `agent_seo_directives`, `cto_code_proposals`, `seo_page_drafts`, `seo_agent_logs`, `audit_recommendations_registry` ; LLM `google/gemini-3-flash-preview` via Lovable AI.
- Absences constatées avant audit (à confirmer/quantifier) : aucune lecture de `architect_workbench`, aucune lecture GSC/GA4, aucun usage des signaux Breathing Spiral (`compute-spiral-signals`), aucun passage par `_shared/aiRouter.ts`, aucun couplage AEO (`aeoRewrites.ts`).
- Contraintes projet applicables : mem://tech/agents/seo-page-generation-fr, mem://tech/architect/shared-workbench-v2-fr, mem://tech/autopilot/breathing-spiral-engine-v5-fr, mem://tech/shared/seo-scoring-v2-fr, mem://tech/ai/llm-task-alignment-fr, mem://tech/ai/groq-routing-override-fr, mem://tech/agents/deployment-and-governance-fr.

## 4. Critères de qualité attendus
| Axe | Cible | Mesure |
|---|---|---|
| Fonctionnel | un run produit ≥ 1 proposition exploitable, 0 route interdite touchée | run manuel + `seo_agent_logs` |
| Cohérence SSOT | le scoring utilise `computeSeoScoreV2`, pas une formule locale dupliquée | lecture code |
| Consommation Workbench | 100 % des items `architect_workbench` `pending` scopés crawlers.fr sont lus et priorisés avant auto-ciblage | requête SQL post-run |
| Non-duplication | aucun item Workbench retraité s'il est déjà `done` / déjà proposé dans `cto_code_proposals` | SQL croisée |
| Coût LLM | < 1,5 ¢ par run, 1 seul appel LLM par page | `ai_gateway_usage` |
| Performance | run < 60 s, pas de timeout wall-time | logs edge |
| Sécurité | RLS + GRANT, aucun accès service_role non gardé, isolation admin | `security--run_security_scan` |
| UX | design system violet/or/noir/blanc, pas d'emoji, pas de bleu IA, boutons bordure + texte | revue de `SeoAgentDashboard.tsx` |

## 5. Benchmark concurrentiel (à corriger par Adrien)
- Surfer SEO / NeuronWriter : scoring sémantique par corpus SERP, mais aucune exécution ni publication.
- Semrush Copilot / Site Audit : détection d'anomalies large, recommandations génériques, zéro rédaction contextualisée à la marque.
- Writesonic / Byword : génération d'articles en masse, aucune boucle d'audit ni gouvernance de publication.
- Barre à atteindre : un agent qui ne redécouvre pas ce que les audits Crawlers savent déjà — il exécute la file de priorités existante (Workbench) et prouve l'impact après déploiement.

## 7. Signaux à mesurer
- `select count(*), status from architect_workbench where site_domain ilike '%crawlers.fr%' group by status`
- `select created_at, target_route, score_before, score_after from seo_agent_logs order by created_at desc limit 30`
- `select edge_function, sum(total_tokens), count(*) from ai_gateway_usage where edge_function = 'agent-seo' group by 1`
- `supabase--edge_function_logs agent-seo` : erreurs, durée, timeouts
- Taux de propositions approuvées vs rejetées dans `cto_code_proposals` (source `seo`)

## Position de l'agent sur la question posée
Oui, brancher l'Agent SEO sur le Workbench est la bonne approche, à trois conditions :
1. **Lecture d'abord, auto-ciblage ensuite** : le Workbench devient la source de priorités ; l'auto-ciblage ne sert que de repli quand la file est vide.
2. **Boucle fermée** : l'agent doit aussi marquer les items consommés (`in_progress` → `done` après approbation) sinon on recrée du bruit à chaque cycle.
3. **Pas de double écriture** : ses propres constats vont dans le Workbench, et les propositions de code restent dans `cto_code_proposals` — un seul artefact par intention, sinon Parménion et l'agent se contredisent.
